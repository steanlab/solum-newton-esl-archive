
# Как разблокировать запись NDEF на NFC-чипе ценников Solum (Type 3 / NFC-F) с телефона

На некоторых ценниках Solum M3 с e-paper стоит NFC-чип с интерфейсом I²C. Телефон определяет его как NFC-F / JIS X 6319-4 / NFC Forum Type 3. Приложения показывают «Writable: No», хотя сам чип по радио запись принимает. 

## Оборудование

- Android-телефон с NFC.
- NFC Tools PRO: нужен раздел «Advanced NFC commands» (вкладка OTHER). Подойдёт любое приложение, которое умеет отправлять «сырые» байты по NfcF.
- Ценник Solum, который в NFC Tools выглядит так: Tag type: JIS 6319-4, Technologies: NfcF, Ndef, System Code: 0x12FC, Data format: NFC Forum Type 3, Writable: No.

## Ход работы

### Шаг 1. Прочитать метку обычным способом

Вкладка READ в NFC Tools, метку приложить к телефону.

*Зачем:* узнать, с чем имеем дело, до любых команд. На экране видно:

- Type 3 / NfcF, System Code 0x12FC. Это стандартный код для NDEF на Type 3. Значит, формат известен, и его правила описаны в спецификации NFC Forum.
- Serial number. Для FeliCa это IDm (8 байт), он понадобится в командах. Например, 02:FE:42:29:0E:98:26:0C.
- Size 27 / 240 Bytes. Под NDEF есть 240 байт (15 блоков по 16 байт), занято 27.
- Writable: No. Главная проблема.

### Шаг 2. Почему «Writable: No»

У Type 3 метки в блоке 0 лежит служебная структура (Attribute Information Block, AIB), а в ней флаг RW Flag: 00 означает «только чтение», 01 означает «чтение и запись». Приложения на Android смотрят на него и показывают «Writable». Если флаг стоит в 00 (вероятно, выставила заводская прошивка), то его можно попробовать изменить.

### Шаг 3. Открыть «сырой» режим NFC Tools

Вкладка OTHER → Advanced NFC commands, в *I/O Class* выбрать NfcF (JIS 6319-4). Приложить метку. В логе появится строка Chip detected: <IDm>. Обычная запись в NFC Tools блок 0 не меняет, поэтому нужны прямые команды.

### Шаг 4. Прочитать блок 0 (AIB)

Команда (IDm подставляется свой из лога, без двоеточий):

    10 06 <IDm> 01 0B00 01 8000

Вводится без пробелов. Пример для 02FE42290E98260C:

    100602FE42290E98260C010B00018000

Что значат байты: 10 это длина команды, 06 это «Read Without Encryption», затем IDm, 01 это одна служба, 0B00 это код службы 0x000B (чтение), 01 это один блок, 8000 это блок номер 0.

Ответ выглядит так:

    1D:07:<IDm>:00:00:01:10:02:01:00:0F:00:00:00:00:00:00:00:00:1B:00:3D

Заголовок 1D 07 <IDm>, статус 00 00 (успех), 01 (число блоков), дальше 16 байт блока 0:

    10 02 01 00 0F 00 00 00 00 00 00 00 00 1B 00 3D

*Почему именно так это читаем:*

| Байт | Значение в примере | Функция |
|------|---------------------------|---------|
| 0 | 10 | версия 1.0 |
| 1 | 02 | максимум блоков за одно чтение |
| 2 | 01 | максимум блоков за одну запись |
| 3-4 | 000F | 15 блоков, то есть 240 байт (совпадает с NFC Tools) |
| 9 | 00 | запись сейчас не идёт |
| 10 | 00 | RW Flag: только чтение (причина «Writable: No») |
| 11-13 | 00 00 1B | длина NDEF = 27 байт (совпадает с NFC Tools) |
| 14-15 | 00 3D | контрольная сумма: сумма байт 0-13 = 0x3D ✓ |

Совпадение размера и длины с тем, что показывал NFC Tools говорит что мы правильно читаем структуру.

### Шаг 5. Сохранить резервную копию

Сделать скриншот READ (или «Save» в меню) и записать ссылку из метки. Также можно снять блоки 1-2 с NDEF-данными:

    12 06 <IDm> 01 0B00 02 8001 8002 

Запись переписывает служебные данные, поэтому откат должен быть возможен.

### Шаг 6. Собрать новый блок 0

1. Взять 16 байт блока 0 из ответа.
2. Байт 10 (одиннадцатый по счёту): 00 → 01.
3. Контрольную сумму (байты 14-15) увеличить на 1: 003D → 003E, потому что сумма байт 0-13 выросла на 1.

Получилось:

    10 02 01 00 0F 00 00 00 00 00 01 00 00 1B 00 3E

Невозможно брать чужой блок 0, потому что у разных меток различаются размер (байты 3-4) и длина NDEF (11-13). Поэтому всегда нужно начинать с блока 0 своей метки и пересчитывай сумму.

### Шаг 7. Записать блок 0

20 08 <IDm> 01 0900 01 8000 <16 байт нового блока 0>
Пример целиком, без пробелов:

        200802FE42290E98260C010900018000100201000F00000000000100001B003E

20 это длина, 08 это «Write Without Encryption», 0900 это код службы 0x0009 (запись), 01 это один блок, 8000 это блок 0.

Метка прошилась, если ответ заканчивается статусом 00:00, например 0C:09:<IDm>:00:00. Любое другое значение означает, что чип запись не принята.

### Шаг 8. Проверить

- Повторить чтение блока 0 (шаг 4): в байте 10 должно быть 01, в сумме 003E.
- Во вкладке **READ** должно стать **«Writable: Yes»**.

### Шаг 9. Записать свои данные

Вкладка **WRITE → Add a record** (Text или URL) → **Write**, держать метку у телефона до подтверждения. Проверить во вкладке READ.

## Откат

Записать блок 0 снова с RW Flag 00 и исходной контрольной суммой (в примере: … 00 00 1B 00 3D).
